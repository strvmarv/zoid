# Releasing zoid

Users install prebuilt binaries via the installer script or `zoid update`
(anonymous, checksum-verified). No tokens live on user machines.

## How a release is wired

- `dist-workspace.toml` sets `create-release = true`: cargo-dist's `host` job
  creates the GitHub Release directly on this repo and uploads the build
  artifacts to it.
- `.github/workflows/release.yml` (generated by `dist generate` — do not hand
  edit; re-run `dist generate` after any `dist-workspace.toml` change) fires
  on `v*` tag pushes, builds the three targets, and uploads the archives,
  checksums, and installer scripts to the Release.
- Release notes come from cargo-dist's own changelog parsing: dist looks for
  a bare `## <version>` section in the root `CHANGELOG.md` matching the tag
  and uses it as the release's announcement body, appending its own install
  one-liners and download table.

## Cut a release

1. Bump the version: edit `[workspace.package] version` in the root
   `Cargo.toml`.
2. Add a `## X.Y.Z` section to the top of **`CHANGELOG.md`** (root)
   describing the release. The version header must be a bare `## X.Y.Z`
   matching the tag (e.g. `## 0.1.0` for tag `v0.1.0`) or dist won't find a
   section to use.
3. Regenerate TUI snapshots — the status bar renders the version, so the
   bump changes ~35 insta frame snapshots: `cargo insta test --accept -p
   zoid-tui`, then confirm `git diff` is version-token-only before staging
   them.
4. Commit: `git commit -am "release: vX.Y.Z"`.
5. Tag and push: `git tag vX.Y.Z && git push origin main --tags`.
6. CI (`release.yml`) cross-compiles the three targets and creates the
   Release with the archives, `sha256.sum`, per-archive `.sha256` files, and
   the `zoid-installer.sh` / `zoid-installer.ps1` installer scripts attached.
7. Verify: the repo's Releases page shows the release with all expected
   assets, and the published notes read correctly (from `CHANGELOG.md`).
8. Smoke-test: on a machine with an older zoid, run `zoid update`.

## First-time install (new machine)

Use the installer script from the latest release (`zoid-installer.sh` on
unix, `zoid-installer.ps1` on Windows). Afterwards, `zoid update` handles
upgrades.

## Push any `v*` tag

Tag pushes are what fire `release.yml` — no subagent should ever push a tag.
